# Common Room — видеособеседования 1-на-1

Статическое SPA для видеозвонков и текстового чата во время собеседования. Приложение использует WebRTC для передачи аудио и видео, а WebSocket — для обмена служебными сообщениями и текстом чата. Сборка и установка зависимостей не нужны.

## Файлы проекта

- `index.html` — структура приложения.
- `style.css` — адаптивный интерфейс.
- `script.js` — медиапотоки, WebRTC и WebSocket signaling.

## Возможности

- Получение разрешения на камеру и микрофон после нажатия «Подключиться».
- Обмен WebRTC offer/answer и ICE-кандидатами через signaling-сервер.
- Буферизация ICE-кандидатов до установки удаленного описания сессии.
- Обработка одновременной отправки offer обеими сторонами.
- Переключение камеры и микрофона, завершение звонка.
- Обработка ухода собеседника и потери signaling-соединения.
- Текстовый чат через WebSocket signaling-сервер.
- Публичные STUN-серверы Google. Для некоторых сетей с жестким NAT одного STUN может быть недостаточно: для гарантированной связи потребуется TURN-сервер.

## Локальный запуск и проверка

Камера и микрофон доступны браузеру только в защищенном контексте: на `localhost` или на HTTPS-сайте. Не открывайте `index.html` напрямую через `file://`.

1. Установите Python 3 либо используйте расширение VS Code Live Server.
2. Откройте терминал в папке проекта и запустите:

   ```powershell
   python -m http.server 8000
   ```

3. Перейдите на [http://localhost:8000](http://localhost:8000).
4. Откройте этот же адрес во второй вкладке или в другом браузере. Для проверки используйте один и тот же signaling endpoint; он ретранслирует сообщения между двумя подключенными клиентами.
5. В обеих вкладках нажмите «Подключиться» и разрешите браузеру доступ к камере и микрофону.
6. Когда обе вкладки покажут, что собеседник подключен, нажмите «Начать звонок» в одной из них. Вторая вкладка автоматически ответит.
7. Проверьте видео, кнопки камеры и микрофона и отправку сообщения в чате. Закройте одну вкладку, чтобы проверить уведомление об уходе собеседника.
8. Остановите локальный сервер сочетанием `Ctrl+C`.

Если порт `8000` занят, запустите `python -m http.server 8001` и используйте `http://localhost:8001`. Если команда `python` не найдена в Windows, попробуйте `py -m http.server 8000`.

## Публикация на GitHub Pages

1. Создайте GitHub-репозиторий и добавьте в его корень `index.html`, `style.css`, `script.js` и `README.md`.
2. Отправьте файлы в ветку `main`.
3. Откройте в репозитории **Settings → Pages**.
4. В разделе **Build and deployment** выберите **Deploy from a branch**, затем ветку `main` и папку `/(root)`, после чего нажмите **Save**.
5. Дождитесь публикации и откройте ссылку, указанную в разделе Pages. HTTPS включается GitHub Pages автоматически; именно HTTPS необходим для доступа к медиаустройствам.
6. Подключите два браузера по опубликованной ссылке и протестируйте звонок так же, как при локальной проверке.

## Настройки signaling

В `script.js` задан endpoint:

```js
const SIGNALING_URL = 'wss://inai-col3.fishrungames.com/signaling/';
```

Сервер должен пересылать JSON-сообщения между клиентами без изменения содержимого и отправлять оставшемуся клиенту `{ "type": "peer-left" }` при отключении второго участника. Для signaling используется WebSocket; WebRTC не зависит от того, размещены ли статические файлы на GitHub Pages.

При отказе в доступе к устройствам разрешите камеру и микрофон для сайта в настройках браузера и подключитесь повторно. Если браузер сообщает об ошибке WebSocket, проверьте доступность signaling endpoint и сетевые ограничения. Стабильность медиа-связи зависит от сети обоих участников; TURN в текущей конфигурации не настроен.
